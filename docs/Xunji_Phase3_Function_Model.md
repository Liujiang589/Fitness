# 独练：第三阶段功能需求与预览模型

版本：0.1 · 2026-10-20（北京时间）

## 本轮结论与范围

第三阶段的功能清单、页面索引、输入输出与验收标准已建立，并制作了独立的本地交互预览。用户本轮要求“先做一个版本看看效果”，因此允许用少量实现验证设计；本轮没有安装工具、改动全局配置或原应用数据，没有生成可安装 APK。

应用暂定名“独练”，未来 Android applicationId 计划使用 app.duolian.local，与 com.trainnote.rn 独立。界面、图形、示例说明与预览源码独立编写。预览内 8 个动作、3 份计划、3 条标有“示例”的训练历史及 1 条示例身体记录用于演示，不代表原版动作总数或用户真实数据。

## 证据与解释规则

- “原版静态证据”：基于合法取得的 APK 中对应模块的有界分析；可以说明客户端存在某逻辑，不能单独证明它在所有模式下实际生效。
- “截图证据”：仅 S01 首页和 S02 动作库列表。没有动作详情页截图；S03 采集失败，不能当作截图证据。此前 PHASE2_HANDOFF.md 的 S01-only 描述早于 S02，本报告采用较新的 S02 文件与 observations。
- “独立需求”：为离线新应用主动设计的规则，不能表述为原版已经采用。
- “预览实现”：HTML/JavaScript 本地原型，不能等同于 Android Room、DataStore、通知或 APK 已交付。

### 动作与媒体批量研究结论

M3822 是可按动作编号读取数据的共用学习组件，使用 description、mp4、uri_360、uri、exetype、MuscleData 等字段；组件在 movekey 改变时重置视频状态。M4003 和 M4004 分别为讲解视频、封面映射，各有 520 个动作键、524 条引用，其中 4 个键对应多条引用；键集合相等。

这是当前讲解映射的覆盖数，不是动作总数。引用通过 CDN_BASE 解析，未请求地址、下载视频或检查权限；不能据此保证素材存在或可离线用。新应用通过自有/获授权的内容补齐。无需逐个手动打开原版动作。

## 输入与输出规则

| 对象 | 输入与校验（预览） | 输出与保存 | 错误行为 |
|---|---|---|---|
| 动作 | 名称/肌群/器械非空≤100字符；说明≤2000字符；默认重量0–1000kg | 独立ID；增改自动保存；详情模板动态读取 | 在计划中使用的动作禁止直接删除；先从计划移除，历史快照不改 |
| 计划 | 名称非空≤100字符；动作至少1项，最多100项，引用现有动作且不重复；日程为说明文本 | 计划ID、名称、日程、动作ID列表 | 无动作不能保存；编辑计划不改已启动训练的快照 |
| 组 | 重量0–1000kg；次数整数0–1000；正式/热身；done布尔；每动作最多100组 | 输入变更保存；完成状态、类型都保留 | 非法输入恢复先前数据并提示；暂停时不能勾完成 |
| 训练 | 同时最多1次活动训练；开始时复制计划动作与默认组 | 活动训练每次操作保存；结束至少完成1组；形成不可随动作编辑改变的快照 | 不覆盖未完成训练；放弃/删除需确认 |
| 休息 | 默认60秒，可设0–600；点完成组时启动；跳过可清零 | 以绝对截止时间存储；暂停存剩余毫秒，恢复重建截止时间 | 过期显示0；后台无系统通知承诺 |
| 身体 | 日期合法；体重20–500kg；体脂可空或0–80% | 按记录ID保存，多条同日记录允许；最近日期显示摘要 | 不接受无效日期或非法数值 |
| 饮食 | 日期、餐次和名称；蛋白/碳水/脂肪各0–1000g，可为0 | 实际食用份量直接录入；4×蛋白+4×碳水+9×脂肪；当天摘要 | 当前摘要只显示今天，其他日期通过备份保留；后续补日期浏览 |
| 饮水 | 快捷250ml或自定义1–10000ml | 当天逐条记录与合计，可删记录 | 不把水转换成热量；2000ml进度只是演示刻度 |
| HIIT | 训练1–600秒，休息0–600秒，轮数整数1–100 | work→rest→下一轮；最后工作段结束即完成；暂停与截止时间保存 | 不在最后一轮追加休息；长时间未活动后按截止时间恢复阶段 |
| 备份 | 本版本格式duolian-backup、version1；JSON≤2MiB；所有字段、ID、范围与引用先校验 | 含动作、计划、历史、活动训练、身体、饮食、饮水、设置、HIIT；不含视频文件 | 通过校验后再提示替换；取消或校验失败不改现有数据；不兼容原版私有备份 |

### 容量与时间口径

预览容量 = Σ（已完成且为正式组的重量kg × 次数），结果保留1位小数。40kg×10次×3组 = 1200kg；热身和未完成组为0。徒手动作暂按输入重量0处理，不推算体重负荷；哑铃数值按照用户实际填入的重量直接计算，不暗中乘2。

M4021 原版还涉及单侧、辅助/自重、减重组与超级组，并有0.4532/0.45换算差异。预览不声称已实现这些分支。未来必须为各分支单列测试与 UI 口径，再扩展统一单位模型。

训练时长 = 当前/暂停时刻 − 开始时刻 − 累计暂停时长。休息基于绝对截止时间，避免依赖逐秒递减造成累计漂移。浏览器被系统挂起时不承诺及时弹出提醒。

## 独立安卓架构与持久化模型（下一阶段设计）

采用 Kotlin + Jetpack Compose + Room + DataStore。以下为新应用的设计方案，并非原版表结构照搬。

| 实体 | 关键字段与关系 | 约束 |
|---|---|---|
| Exercise | id、name、muscle、equipment、defaultWeight、notes、isArchived | 被计划引用时采用归档/显式解除引用；历史不级联删除 |
| MediaReference | id、exerciseId、kind、localUri、mimeType、licenseNote | 通过安卓文件选择器授权；禁止默认连接原版CDN |
| Plan / PlanExercise | id、name；planId、exerciseId、order、defaultSets、restSeconds | 名称非空；至少一个动作；动作顺序显式存储 |
| TrainingSession | id、planId可空、titleSnapshot、status、start/end、pausedDuration | ACTIVE最多一条；结束事务原子更新 |
| SessionExercise | id、sessionId、exerciseId可空、nameSnapshot、order | 保留历史名称与动作配置快照 |
| SetRecord | id、sessionExerciseId、order、weightGrams、reps、setType、completedAt | 重量内部整数克；展示kg；后续特殊组另建关联 |
| ActiveTimer | sessionId、restDeadlineEpochMs、remainingMs、pausedAt | 开始/暂停/结束与训练状态同事务保存 |
| BodyMeasurement | id、date、weightGrams、bodyFatBasisPoints可空 | 独立本地全历史，不依赖账号 |
| NutritionEntry / WaterEntry | id、date、meal、name、三大营养素；id、date、amountMl | 热量由营养素计算；饮水独立存表 |
| HiitConfiguration / Run | work/rest/rounds；阶段、截止时间、暂停信息 | 保存用户配置及可恢复状态 |

DataStore 仅放偏好设置（默认休息、显示单位、主题），训练和营养记录进 Room。导入先解析与校验，再在单事务替换或合并；默认导入前生成快照备份。备份通过 Storage Access Framework 导出到用户所选目录；安卓版将支持经过授权的媒体目录引用与可选媒体打包。

安卓通知、锁屏计时和后台行为需按目标SDK验证并单独设计；当前没有配置SDK或依赖版本，不把设计当成已构建。阶段四开始时以实际安装工具版本和官方文档核对兼容性。

## 优先级与交付顺序

1. P0：原生动作与计划、普通/热身组、训练暂停恢复、休息、历史与容量、备份恢复；通过 Room重开与断网测试。
2. P1：身体、饮食、饮水全历史；授权媒体播放；原生HIIT；通知权限及后台提醒验证。
3. P2：超级组、减重组、辅助重量、单位换算、周期计划、更多统计、挑战规则。
