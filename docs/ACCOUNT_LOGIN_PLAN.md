# 独练：账号登录接入准备

核对日期：2026-10-28。状态：方案与申请信息已准备，真实账号服务尚未接通。

## 本次补充：申请路线需先满足主体条件

用户已确认：尚无腾讯云 / CloudBase、微信开放平台或 QQ 互联账号；只有个人身份，没有营业执照。已选择先准备申请方案与资料。

腾讯云 2025-09-12 公告明确，自 2025-09-18 起不再新增个人认证自用短信资质；2026-04-20 更新的签名审核标准也不再支持新建个人自用签名。因此，下文“手机号优先”是资质满足后的目标，不能按“注册个人账号即可发验证码”执行。个人申请他用签名需要真实的企事业单位授权，本项目尚不具备。未开通任何付费资源。

当前可评估的过渡方案是 CloudBase 邮箱验证码登录（包含接收验证码的 QQ 邮箱），不等于 QQ 互联授权登录。官方支持内置邮件代发，但仍需用户自己的云环境，并核对套餐、额度及发送限制。用户尚未决定采用邮箱过渡方案，不能自行替换原目标或声称已上线。

微信、QQ 的具体主体资格和应用审核条件，需要在各自当前申请控制台核对。不能从高德个人认证成功推断微信、QQ 登录同样可用。网站应用和安卓移动应用分别准备资料，iPhone PWA 不填写虚构的原生 iOS Bundle ID。

申请材料见项目根目录 `独练-账号登录申请资料-20261028/`；前一轮只整理申请资料，没有改动应用。后续安卓版 V1.26 的入口准备工作见下文及 `V1_26_GUIDE.md`。账号隔离仍是待实现、待测试的要求。

依据：[腾讯云个人短信资质调整公告](https://cloud.tencent.com/announce/detail/2127)、[签名审核标准](https://cloud.tencent.com/document/product/382/39022)、[CloudBase 邮箱验证码登录](https://docs.cloudbase.net/authentication-v2/method/email-login)。

## 目标与边界

用户后续已澄清：苹果网页版暂停，注册登录作为独立事项，仅继续安卓端。安卓 V1.26 已编写账号准备页面；输入与提交保持禁用，尚无身份验证、账号隔离或在线注册。此处后文跨端设计仅是未来方向，不属于本轮实现范围。

安卓和 iPhone 网页体验版使用同一个服务端用户 ID，支持手机号验证码、微信、QQ 的登录或绑定。
三种登录方式关联同一个独练账号；不能按昵称、头像或用户手填 QQ 号判断是同一个人。
保留不登录的本地体验。登录不代表训练数据已经云同步，本次准备不上传现有训练、身体或饮食记录。

## 当前项目核对

- 安卓：原生 Kotlin / Compose / Room，目前没有账号后端。
- 网页：PWA，本地浏览器存储；目前没有账号服务，网页开放访问不等于账号登录。
- 网页托管在 Sites，其内置 ChatGPT 登录与用户要求的手机号 / 微信 / QQ 登录不是同一套服务。
- 需要单独接入支持这些身份来源的认证服务；不能把网站访问权限当作独练账号。
- 已检查当前连接工具并搜索插件，未发现可直接管理腾讯云 / CloudBase 账号的匹配连接。可在用户提供账号环境后通过官方控制台或受支持的服务 API 配置，不向前端写入服务端密钥。

## 建议推进顺序

### 第一阶段：手机号验证码 + 账号基础

1. 确定用户名下的云账号、认证服务、地域、固定 HTTPS 域名及可接受的套餐预算。
2. 申请并审核短信签名、验证码模板，配置发送渠道。
3. 实现注册 / 登录、验证码过期与失败反馈、服务端发送限流、退出、会话失效、账号管理。
4. 前端按钮倒计时仅作为体验提示，不能替代服务端限流；不提供通用测试验证码。
5. 原游客记录保持独立；首次登录时让用户决定是否将当前设备记录归入本账号，先保留备份。
6. 用户 A 退出后，用户 B 不能看到 A 的训练、饮食和体重。按服务端 UID 划分缓存与数据权限。

CloudBase 是候选方案，尚未替用户开通或购买。官方短信登录文档目前注明仅支持上海地域，且需要接入短信服务商、签名与模板。必须在实际环境中再次核对可用地域和套餐后再开通。

### 第二阶段：微信登录与绑定

- 申请微信开放平台对应的移动应用 / 网站应用和登录能力；两端分别核对申请配置。
- 将 AppSecret 等放在认证服务的受保护配置中，不打进 APK、前端 JS 或压缩包。
- 浏览器授权跳转须校验一次性 state，限制回调地址；取消授权应返回登录页并保留原页面。
- CloudBase 当前文档说明：未关联用户可能返回 `not_found`，需先通过其他方式创建账号，再绑定微信。这也是建议先做手机号账号的原因。
- iPhone Safari、微信内置浏览器与安卓 App 的授权路径分别测试，不把微信网页扫码流程当作所有手机环境都能一键唤起。

### 第三阶段：QQ 登录与绑定

- 在 QQ 互联申请对应网站应用和移动应用，完成审核，配置 AppID、AppKey、回调信息。
- CloudBase 公开的基础登录列表没有直接列出普通 QQ 登录；不得据此声称已原生支持。接入前核对可用身份源或通过受支持的自定义登录与 QQ 官方 OAuth 对接。
- QQ 授权结果在受信任服务端验证，确认应用和用户身份后映射到独练 UID。
- 绑定、解绑需要已有账号的近期认证；不能只凭昵称或同一个头像合并账号。

## 联调完成标准

- 新用户、老用户登录；验证码错误、过期、频繁发送；网络断开和重试。
- 微信 / QQ 授权成功、取消、账号未绑定、回调被篡改、授权码重复使用。
- 同一个人绑定多个登录方式后仍使用同一个 UID；账号冲突不自动合并。
- 在同一手机退出 A 并登录 B，不能读取 A 的私有记录。
- 跨设备登录身份一致；未实现云同步前不显示“数据已同步”。
- 原有本地记录迁移前备份，迁移失败可恢复，不覆盖其他账号记录。
- Android 真机 + iPhone Safari / 主屏幕网页 App 分别联调；桌面模拟测试不能代替这些验收。
